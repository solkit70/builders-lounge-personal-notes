## 요약

김진영님은 검색 AI를 실제 사용자처럼 행동하는 User Agent로 시험하고, Evaluator가 검색 경험과 태스크 성공 여부를 평가한 뒤 Auditor가 평가 기준의 일관성을 검토하는 멀티 에이전트 평가 시스템을 발표했다. 이를 이용해 검색 시스템의 결과와 사용자 경험을 비교하고, 실제 사용자 실험 전에 가상 사용자 실험을 수행할 가능성을 설명했다.

발표 자료의 표제는 **「AI가 AI를 평가하는 시대: 멀티 에이전트 평가 시스템의 설계와 구현」**이다. 발표자는 Builders Lounge 멤버인 김진영님이며, 슬라이드에는 네이버 검색 US 디렉터로 소개되어 있다.

## 시스템 구조

| 역할 | 기능 |
|---|---|
| User Agent | 검색 태스크를 수행하며 검색 시스템을 실제 사용자처럼 이용한다. 답변을 읽고 다음 행동이나 질문을 이어간다. |
| Evaluator | 태스크의 성공 기준에 따라 결과를 평가한다. 검색 경험, 목표 달성, 답변의 유용성, 정보와 출처 품질 등을 살핀다. |
| Auditor | 시스템별 평가가 같은 기준으로 이루어졌는지 검토해 비교의 일관성을 확인한다. |
| 평가 대상 | 여러 검색 모델 또는 검색 서비스를 같은 태스크로 시험하고 결과를 비교한다. |

시연 리포트는 결과 점수와 사용자 에이전트의 대화·판단 흐름 및 경험 관련 평가를 함께 보여준다. 시연 모델의 버전과 점수는 전사 검토본에 불확실성이 있어 일반 사양으로 인용하지 않는다.

## 평가 기준과 Ground Truth

태스크를 만들 때 기대 답, 필요한 내용, 오류 기준 등을 바탕으로 Success Criteria를 작성해 평가 기준점으로 삼는다. 발표 중 김진영님은 미리 준비한 답이 정말 Ground Truth인지 의문을 제기했다. 검색 지식은 질의와 시점에 따라 바뀔 수 있고, 믿을 만한 출처로 기준을 만드는 일은 비용이 들며 계속 갱신해야 하기 때문이다.

전사본에서는 답을 미리 제공한다고 오해받지 않도록 “정답” 대신 성공 기준이라고 부르는 방향도 언급한다. 평가 에이전트가 매번 별도로 검색하지 않고 태스크에 주어진 기준을 이용하면 비용을 줄일 수 있다. 이 시스템은 설정된 성공 기준에 따라 결과를 비교하는 것이며, 모든 질의에 불변의 정답을 보증하는 것으로 설명하지 않는다.

## 평가 모델과 지표

시연에서 Evaluator와 Auditor의 기본 모델은 GPT로 설정되어 있었으며, 다른 모델도 사용할 수 있다고 설명했다. 외부 벤치마크와 정합성이 검증됐다고 발표한 것은 아니다. 김진영님은 내부에서 사용하는 지표와 결과의 일치 여부를 확인하려 한다고 답했다. 실제 고객 피드백·NPS와의 직접 비교 질문에는 내부 지표 확인에 초점을 둔 답변을 했다.

Evaluator는 매 평가마다 별도로 검색하는 Tool Calling을 하지 않고, 태스크에 적힌 답의 방향과 성공 기준을 사용한다고 설명했다. 이는 비용과 실행 부담을 줄이는 설계 선택으로 제시됐다.

## 가상 사용자 실험

User Agent의 활용 사례로 실제 사용자를 대상으로 한 실험 전에 가상 사용자 집단으로 서비스나 제품을 시험하는 방식을 소개했다. 대표성 있는 사용자 집단을 여러 개 시뮬레이션해 초기 반응을 탐색할 수 있다는 구상이다. 이는 실제 사용자를 완전히 대체한다고 발표된 것이 아니다.

이 접근은 페르소나를 어떻게 정의하느냐에 좌우된다. 인구조사 자료나 공개 데이터셋을 참고할 수 있고, 실제 사용자 데이터가 쌓이면 사용자 에이전트 행동을 조정하는 데 쓸 수 있다고 설명했다. “Every Simulate User”로 들리는 업체·프로젝트명은 확인 필요로 표시되어 특정 회사 이름으로 단정하지 않는다.

## 개발 과정에서 사람과 AI의 역할

김진영님은 AI로 초기 프로토타입을 만드는 일은 쉬웠지만 다른 사람도 쓸 수 있도록 완성도를 높이는 데는 여전히 시간이 필요하다고 말했다. 과거 개발팀과 일한 경험이 도움이 되었고, 필요와 우선순위를 정하고 프로젝트를 이끄는 사람의 역할이 이어진다는 의견이 나왔다.

토론에서는 큰 목표를 작은 하위 작업으로 나누고 결과를 확인해야 한다는 점을 다뤘다. 박창수님은 Seattle Tech Week 자료를 뚜렷한 주제와 결론 없이 한꺼번에 맡겼다가 원하는 결과를 얻기 어려웠던 경험을 들었다. 손민수님은 요구사항을 하위 작업으로 나누고 사람이 검토해 합치는 과정의 필요성을 덧붙였다.

검색과 AI 요약의 차이도 논의했다. 검색은 여러 출처를 읽고 비교하며 분야에 대한 감과 판단 맥락을 쌓게 하지만, 요약된 답만 받으면 그 과정이 줄어들 수 있다는 우려를 고가공 식품과 통곡물의 비유로 설명했다. 마지막에는 에이전트의 중간 설명을 살펴보는 것이 XAI와 모델 동작을 이해하는 데 도움이 될 수 있다는 경험을 나눴다. XAI 도구명은 전사에서 불명확하므로 확정하지 않는다.

## Bila AI 답변 가이드

- 시스템은 **User Agent → Evaluator → Auditor**의 역할 분담으로 설명한다.
- User Agent가 검색을 수행하고, Evaluator가 태스크 성공 기준으로 평가하며, Auditor가 평가의 일관성을 검토한다.
- 핵심은 답변 점수만 매기는 것이 아니라 사용자 경험과 태스크 수행 과정을 시뮬레이션해 검색 시스템을 비교하는 방법이다.
- Success Criteria는 평가 기준이며 모든 질문의 절대적·영구적인 정답을 뜻하지 않는다.
- 가상 사용자 실험은 실제 실험 전의 탐색 가능성으로 소개됐다. 실제 사용자를 완전히 대체한다고 말하지 않는다.
- 내부 지표와의 정합성을 확인하려는 계획이 언급됐다. 외부 벤치마크나 NPS 검증이 완료됐다고 말하지 않는다.
- 모델 버전, 일부 고유명사, XAI 도구명은 전사에서 미확정이다. 정확한 명칭이나 수치는 영상 확인 전까지 단정하지 않는다.
- 손민수님의 발표와 혼동하지 않는다. 손민수님은 별도의 멀티 에이전트 시스템 장애 대응 프로젝트를 발표했다.
